Automated Client Orientation Scheduling & Zoom Integration

Designed a guided Salesforce scheduling experience that coordinates in-person and virtual client orientations, securely provisions location-specific Zoom meetings, and connects Salesforce events with website registration and communication workflows.

Salesforce Screen FlowQueueable ApexZoom REST APIServer-to-Server OAuthCustom MetadataWebsite integration

Project overview

Orientation scheduling previously depended on manual coordination across disconnected systems. The solution consolidates event generation in Salesforce, distinguishes the operational paths for physical and virtual attendance, and connects virtual orientation events to dedicated Zoom host accounts based on location.

Location-based host selection

Dedicated Zoom host accounts are assigned by location, such as Calgary, Edmonton, Airdrie, Strathmore and Cochrane. The Apex implementation queries active Zoom_Host_Mapping__mdt records and resolves a host from the event location, matching configured label, developer name or location API value (case-insensitively).

StepImplemented behavior
Primary hostUse the location's configured host email or Zoom user ID. If no location match is found, the class can use a supplied host override or configured default host.
Alternate hostsRead optional location-specific alternate host emails, remove duplicates and the primary host, and validate each candidate through the Zoom Users API for active, licensed eligibility.
Meeting ownerCreate the meeting under the primary location account, not an alternate host. Alternate hosts support convenient meeting starts.
Alternate-host failureIf Zoom rejects the request with an HTTP 400 response containing alternate hosts, retry creation without the alternate-host setting.
Unresolved hostSet the Salesforce event's Zoom status to Failed and capture the missing-host mapping message.

Meeting payload

Configured meeting experience

Meeting title, scheduled start, duration, agenda and optional alternate hosts; waiting room enabled, participants muted on entry and join-before-host disabled.

Success response

Saved to the Salesforce event

Virtual_URL__c ← join_url; Zoom_Id__c ← meeting ID; Zoom_Host__c ← selected primary host; Zoom_Status__c ← Created.

Failure handling

Observable integration state

Zoom_Status__c ← Failed; Zoom_Error_Message__c records API or Apex errors. Event updates use partial-success DML.

Technical quality and testing

The supplied ZoomMeetingQueueableTest demonstrates HTTP callout mocks for Zoom user verification and meeting creation, including eligible and ineligible users, alternative-host rejection and API error conditions. These are code-level test scenarios, not a claim that all production outcomes have been independently verified.

Measurement note: The 82% registration improvement is a project-reported result. Attendance was also reported to improve, without a specific percentage supplied.

Design boundary: The event-type choice and invocation of virtual meeting provisioning are guided Flow responsibilities; the supplied Queueable Apex class itself processes the event IDs it receives and does not establish the Flow's decision logic.
